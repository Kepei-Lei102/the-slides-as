A branch chooses the next action

DECLARE Age, Price : INTEGER
INPUT Age
IF Age >= 12 THEN
    Price ← 8
ELSE
    Price ← 5
ENDIF
OUTPUT Price
Evaluate the condition once. Execute only the selected branch.
ENDIF closes the choice. The output afterwards runs whichever branch was selected.
With no ELSE, a false condition simply skips the body.

Every comparison asks a complete question

ExpressionAt Age = 12
(Age >= 12) AND (Age <= 17)TRUE
(Age < 12) OR (Age > 17)FALSE
NOT (Age = 12)FALSE
Age <> 12FALSE
Use = to compare, ← to assign. AND and OR join Boolean expressions.
Age = 12 OR 13 is incomplete: write (Age = 12) OR (Age = 13).

A later IF is a separate decision

DECLARE Price : INTEGER
DECLARE Member : BOOLEAN
Price ← 8
Member ← TRUE
IF Member THEN
    Price ← Price - 2
ENDIF
OUTPUT Price
This outputs 6. The membership test can follow either age branch.
Two independent IF statements can both run.
A nested IF is different: control must enter the outer branch before reaching the inner test.

Which IF owns this ELSE?

DECLARE Age : INTEGER
DECLARE Member : BOOLEAN
INPUT Age
INPUT Member
IF Age >= 12 THEN
    IF Member THEN
        OUTPUT "Member ticket"
    ELSE
        OUTPUT "Standard ticket"
    ENDIF
ELSE
    OUTPUT "Child ticket"
ENDIF
Age 11, Member TRUE: Child ticket. The inner IF is never reached.
Age 12, Member FALSE: Standard ticket.
Match each ENDIF to its IF. Indentation makes ownership visible.

One value chooses a menu branch

DECLARE Choice : INTEGER
INPUT Choice
CASE OF Choice
    1 : OUTPUT "Tea"
    2 : OUTPUT "Juice"
    OTHERWISE : OUTPUT "Water"
ENDCASE
Read the cases in order. Execute the first matching branch, then leave CASE.
OTHERWISE handles unmatched values. It comes last.

WHILE checks before entry

DECLARE Count : INTEGER
Count ← 3
WHILE Count < 3
    OUTPUT Count
    Count ← Count + 1
ENDWHILE
OUTPUT "Done"
The first test is 3 < 3: FALSE. The body runs zero times. Output: Done.
Start at 1 instead: output 1, 2, then Done.
Test again before every pass. TRUE continues; FALSE leaves.

REPEAT works first, then tests

DECLARE Count : INTEGER
Count ← 3
REPEAT
    OUTPUT Count
    Count ← Count + 1
UNTIL Count >= 3
OUTPUT "Done"
The body runs before the test. Output: 3, then Done.
UNTIL TRUE means stop. FALSE means go back for another pass.
Start at 1: output 1, 2, then Done. The test sees the updated value.

Ask at least once, stop on valid input

DECLARE Mark : INTEGER
REPEAT
    INPUT Mark
UNTIL (Mark >= 0) AND (Mark <= 100)
OUTPUT Mark
Inputs arrive in order: −1, 101, 75.
The tests are FALSE, FALSE, TRUE. Output: 75.
The stop condition describes valid input. Reversing it accepts the first invalid value.

FOR visits a sequence of counter values

DECLARE Index : INTEGER
FOR Index ← 1 TO 4
    OUTPUT Index
NEXT Index
Output: 1, 2, 3, 4. TO includes the endpoint when the step reaches it.
Default STEP is 1. NEXT belongs to the named counter.
Four counter values means four executions. The count is known before starting.

STEP chooses the direction and gap

A bound can be inclusive without being reached. STEP must make progress in the intended direction. Never use zero.

Each outer pass starts a fresh inner run

DECLARE Row, Seat : INTEGER
FOR Row ← 1 TO 2
    FOR Seat ← 1 TO 3
        OUTPUT Row, ":", Seat
    NEXT Seat
NEXT Row
Output: 1:1, 1:2, 1:3, 2:1, 2:2, 2:3.
The inner counter starts at 1 for each row. Six visits, not five.
A running total for the whole room starts before both loops.

A changing counter can still miss the exit

DECLARE Count : INTEGER
Count ← 1
REPEAT
    OUTPUT Count
    Count ← Count - 1
UNTIL Count = 4
First outputs: 1, 0, −1, −2… The update moves away from 4.
Repair the update to Count ← Count + 1. Then outputs are 1, 2, 3.
Removing the update creates a different failure: the condition never changes.

An instruction is precise when you can trace it

Exit: Count starts at 4. WHILE Count < 4 surrounds an increment. How many body executions?
Now use REPEAT with the same increment and UNTIL Count >= 4. How many? Why?
Keep: test position, truth direction, progress, exact state changes.
